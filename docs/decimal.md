# Decimal 型の仕様

Zustral の組み込みの10進固定小数点型 `Decimal[P, S]` の仕様である。
金額のように、桁と丸めを間違えてはいけない値を扱うための型である。

この文書は、何をどう書けて、何が起きるかだけを書く。
なぜそう決めたかは、各節の末尾に挙げた issue の解消コメントにある。
決定の索引は issue #9 にある。

**状態。** 仕様は決まっている。実装はまだない。
使い捨ての試作が `docs/research/decimal-prototype/` にあり、この仕様の大半を動かして確かめてある。

## 1. 型

`Decimal[P, S]` は、全体で P 桁、小数点より下が S 桁の、符号付きの10進数である。
P を精度、S をスケールと呼ぶ。

```austral
let price: Decimal[9, 2] := 1980.00;
let rate: Decimal[5, 4] := 0.0825;
```

- P と S は整数リテラルで書く。型変数にはできない。
- 1 ≤ P ≤ 38、0 ≤ S ≤ P である。範囲の外はコンパイルエラーになる。
- 表せる値は、絶対値が 10 の (P − S) 乗未満で、小数部が S 桁までの数である。`Decimal[7, 2]` なら −99999.99 から 99999.99 までである。
- P か S が違えば、別の型である。型の違う Decimal の間に、暗黙の変換はない。
- Free の型である。自由に複製でき、破棄できる。
- `Decimal` という型名は、`Int32` と同じく、取り込まずに使える。

（issue #4、#5、#24）

## 2. 実行時の表現

値は係数で持つ。係数は、値を 10 の S 乗倍した整数である。
係数は符号付き128ビット整数に入る。大きさは16バイト固定で、ヒープを使わない。

同じ型では、1つの値に係数は1つしかない。1.50 と 1.5 は同じ係数になる。

（issue #1、#4、#5）

## 3. リテラル

新しい構文はない。`1.23` や `5` という数値リテラルが、Decimal が期待される位置で、その型になる。

- 符号（`+` か `-`）と、桁区切り（`1'000.25`）は使える。
- **値がその型で正確に表せるリテラルだけを受け付ける。** 表せなければコンパイルエラーになる。丸めも切り捨てもしない。`Decimal[7, 2]` に対する例は次のとおりである。

  | リテラル | 結果 |
  |---|---|
  | `1.5` | 通る。1.50 になる |
  | `1.230` | 通る。値は 1.23 である |
  | `5` | 通る。5.00 になる |
  | `1.234` | エラー。小数3桁目が 0 でない |
  | `100000.00` | エラー。整数部が5桁を超える |

- 指数表記（`1.5e3`）は、Decimal のリテラルにならない。
- 16進、2進、8進、文字のリテラルは、Decimal のリテラルにならない。
- Decimal が期待されていない位置では、小数点付きのリテラルは今までどおり `Float64` である。

リテラルの型は、書いた位置で決まる。

- 型が届く位置（4節）では、届いた型になる。
- `*` の片方と、`divide`、`round`、`exact`、`widen` の引数では、**値を正確に表せる最も小さい型**になる。`2` は `Decimal[1, 0]`、`0.0825` は `Decimal[4, 4]`、`1.50` は `Decimal[2, 1]` である。38桁に収まらないリテラルはコンパイルエラーになる。
- どちらでもない位置では、型注釈で型を与える。`1.23 : Decimal[7, 2]` と書く。

リテラルだけからなる式は、次のように扱う。

- Decimal が期待される位置に書いた、リテラルだけの `+`、`-`、`*` の式は、1つのリテラルとして扱う。コンパイル時に10進で正確に計算し、結果が期待される型で正確に表せるかを検査する。
- リテラルだけの式に `/` があれば、Decimal が期待される位置ではコンパイルエラーになる。

（issue #14、#12、#23）

## 4. 型が届く位置

結果の型を位置から取る演算（`divide`、`round`、`exact`、`widen`、`parse` と、その `checked` の形）と、リテラルは、書いた位置から型を受け取る。

型が届く位置は次のとおりである。

| 位置 | 例 |
|---|---|
| `let` と `var` の型注釈、定数の宣言 | `let q: Decimal[9, 4] := divide(a, b, m);` |
| `return` | 戻り値の型が届く |
| 型注釈 | `divide(a, b, m) : Decimal[9, 4]` |
| 代入の右辺 | `total := 0;`、`r.amount := round(x, m);` |
| `+`、`-`、比較の両辺 | `widen(a) + tax` は、`tax` の型が `widen(a)` に届く |
| 関数の引数、レコードや union の構成子の欄 | `show(1.23)`。宣言された型が具体的な Decimal の場合に限る |
| `if` 式の枝 | `if premium then 0.0500 else 0.0825` |

`+`、`-`、比較では、式全体に届いた型も両辺に届く。
両辺とも自分では型が決まらず、外からも届かないときは、コンパイルエラーになる。

型が届かない位置は次のとおりである。ここでは型注釈を書く。

- `*` の両辺と、`divide` の割られる数と割る数。
- 型変数として宣言された引数や欄。`Some(value => 1.23)` は通らず、`Some(value => 1.23 : Decimal[7, 2])` と書く。

型が届かない位置に、結果の型を位置から取る演算を書くと、コンパイルエラーになる。既定の結果の型はない。

（issue #6、#15、#23）

## 5. 演算の一覧

| 書き方 | 入力 | 結果の型 | 丸め | 失敗 |
|---|---|---|---|---|
| `a + b`、`a - b` | 同じ型どうし | 入力と同じ | なし | 桁あふれで止まる |
| `checkedAdd(a, b)`、`checkedSubtract(a, b)` | 同じ型どうし | `Option`（入力と同じ型） | なし | `None` |
| `-a` | | 入力と同じ | なし | しない |
| `a * b` | 型が違ってよい | `Decimal[P1 + P2, S1 + S2]` | なし | しない |
| `divide(a, b, mode)` | 型が違ってよい | 位置から取る | あり | 桁あふれとゼロ除算で止まる |
| `checkedDivide(a, b, mode)` | 型が違ってよい | 位置から取る `Option` | あり | `None` |
| `widen(x)` | Decimal か整数型 | 位置から取る | なし | しない |
| `exact(x)` | Decimal か整数型 | 位置から取る | なし | 正確に表せなければ止まる |
| `checkedExact(x)` | Decimal か整数型 | 位置から取る `Option` | なし | `None` |
| `round(x, mode)` | Decimal、整数型、`Float64` | 位置から取る | あり | 桁あふれで止まる |
| `checkedRound(x, mode)` | Decimal、整数型、`Float64` | 位置から取る `Option` | あり | `None` |
| `approximate(x)` | Decimal | `Float64` | 最も近い値 | しない |
| `=`、`/=`、`<`、`<=`、`>`、`>=` | 同じ型どうし | `Bool` | なし | しない |
| `print(x)`、`printLn(x)` | Decimal | `Unit` | なし | しない |
| `parse(text)` | `Span[Nat8, R]` | 位置から取る `Option` | なし | `None` |

- `+` と `-` の両辺の型が違えば、コンパイルエラーになる。`widen` でそろえてから足す。
- `*` で P1 + P2 が 38 を超えると、コンパイルエラーになる。先にどちらかを狭い型へ変換してから掛ける。
- `/` は Decimal には使えない。コンパイルエラーになり、`divide` を使う。
- 演算子に優先順位はない。2つ以上の演算子を並べるときは、括弧で順序を書く。これは今の言語の規則である。
- Decimal は、`TrappingArithmetic` と `ModularArithmetic` のインスタンスではない。

```austral
let subtotal: Decimal[11, 2] := (price_a + price_b) - discount;
let tax: Decimal[11, 2] := round(subtotal * 0.0825, NearestEven());
let unit: Decimal[9, 4] := divide(subtotal, 3, NearestEven());
let total: Decimal[15, 2] := widen(subtotal);
```

（issue #6、#12、#15、#17）

## 6. 結果の決め方

どの演算も、次の順で結果を決める。

1. 数学的に正確な値を求める。途中の値を何桁かで切り詰めることはしない。
2. 丸めモードを取る演算なら、結果の型のスケールへ、1回だけ丸める。
3. 結果の型の精度 P と比べる。係数の絶対値が 10 の P 乗以上なら、桁あふれである。

丸めてから桁あふれを検査する。
999.96 を `Decimal[4, 1]` へ `NearestAwayFromZero` で丸めると、1000.0 に丸め上がって桁あふれになる。

（issue #7、#8）

## 7. 丸め

暗黙の丸めはない。既定の丸めモードもない。
桁を落としうる演算は、必ず丸めモードを引数に取る。丸めモードを取るのは、`divide` と `round`、その `checked` の形だけである。

丸めモードは、組み込みの union 型 `RoundingMode` の値である。case は次の7つである。
右の4列は、小数2桁へ丸めた結果である。

| case | 意味 | 2.345 | 2.355 | −2.345 | 2.344 |
|---|---|---|---|---|---|
| `NearestEven` | 最も近い値。ちょうど半分なら偶数へ（銀行丸め） | 2.34 | 2.36 | −2.34 | 2.34 |
| `NearestAwayFromZero` | 最も近い値。ちょうど半分なら 0 から遠い方へ（四捨五入） | 2.35 | 2.36 | −2.35 | 2.34 |
| `NearestTowardZero` | 最も近い値。ちょうど半分なら 0 に近い方へ | 2.34 | 2.35 | −2.34 | 2.34 |
| `AwayFromZero` | 0 から遠い方へ（切り上げ） | 2.35 | 2.36 | −2.35 | 2.35 |
| `TowardZero` | 0 に近い方へ（切り捨て） | 2.34 | 2.35 | −2.34 | 2.34 |
| `TowardGreater` | 大きい方へ | 2.35 | 2.36 | −2.34 | 2.35 |
| `TowardLesser` | 小さい方へ | 2.34 | 2.35 | −2.35 | 2.34 |

「丸めが要るなら失敗にする」は、丸めモードではない。`exact` と `checkedExact` を使う。

（issue #7）

## 8. 失敗

桁あふれしうる演算には、2つの形がある。

- **止まる形。** 失敗すると、メッセージを出してプログラムを止める。演算子と、`checked` の付かない名前の演算がこれである。整数の桁あふれと同じ扱いである。
- **検査する形。** 結果を `Option` で返し、失敗なら `None` にする。`checked` の付く名前の演算がこれである。失敗の理由は返さない。

ゼロ除算も同じに扱う。`divide` は止まり、`checkedDivide` は `None` を返す。

黙って桁を落とす演算はない。あふれた分を捨てて続ける演算も、上限に張り付かせる演算もない。

（issue #8）

## 9. 変換

型注釈 `式 : 型` は、値を変換しない。変換は、次の3つの演算で書く。変換先の型は、位置から取る。

| 演算 | 意味 | 失敗 |
|---|---|---|
| `widen(x)` | 元の型のどの値も、変換先で正確に表せる変換 | しない。表せない組み合わせはコンパイルエラー |
| `exact(x)` | 値を変えずに移す変換 | 値が変換先で正確に表せないとき |
| `round(x, mode)` | 変換先のスケールへ丸める変換 | 丸めた後の桁あふれ |

`widen` が通るかどうかは、型だけで決まる。

- `Decimal[P, S]` から `Decimal[P', S']` へは、S' ≥ S かつ P' − S' ≥ P − S のときに通る。
- 整数型からは、その型の最大の桁数が P' − S' 以下のときに通る。桁数は次のとおりである。

  | 型 | 桁数 |
  |---|---|
  | `Nat8`、`Int8` | 3 |
  | `Nat16`、`Int16` | 5 |
  | `Nat32`、`Int32` | 10 |
  | `Int64` | 19 |
  | `Nat64`、`Index`、`ByteSize` | 20 |

変換の元と先は、次のとおりである。

- `widen` は、Decimal か整数型から Decimal へ。
- `exact` は、Decimal か整数型から、Decimal か整数型へ。どちらか一方は Decimal である。
- `round` は、Decimal、整数型、`Float64` から、Decimal か整数型へ。`Float64` からは、その2進の値を正確な値として丸める。NaN と無限大は失敗になる。
- Decimal から `Float64` へは、`approximate(x)` を使う。最も近い `Float64` を返す。Decimal の値が正確に保たれない変換は、これ1つである。

（issue #15）

## 10. 比較

`=`、`/=`、`<`、`<=`、`>`、`>=` は、同じ型の Decimal どうしで使える。
型が違えばコンパイルエラーになる。`widen` でそろえてから比べる。

片方がリテラルなら、リテラルは相手の型になる。左右どちらにあっても同じである。

比較は全順序である。NaN も負のゼロもない。

stdlib の `Standard.Equality` と `Standard.Order` のインスタンスは、コンパイラが作らない。

（issue #15）

## 11. 文字列

Decimal の正準の表記は1つである。

- 負のときだけ `-` を付ける。
- 整数部は、先頭の 0 を付けずに、最低1桁を書く。
- 続けて、小数点と、ちょうど S 桁の小数部を書く。S が 0 なら、小数点も書かない。
- 桁区切り、指数、正の符号、空白は付けない。

`Decimal[7, 2]` では、1.5 は `1.50`、−0.05 は `-0.05`、0 は `0.00` になる。

`print` と `printLn` は、すべての Decimal の型で使える。出力は正準の表記である。

`parse(text)` は、文字列から Decimal を読む。結果は位置から取る `Option` である。

- 受け付ける形は、符号（省略可）、1桁以上の数字、省略できる小数点と1桁以上の数字である。桁区切り、指数、前後の空白は受け付けない。
- 値がその型で正確に表せるときだけ `Some` を返す。丸めない。`Decimal[7, 2]` に対して、`"1.5"` と `"1.500"` は読め、`"1.234"` と `"100000.00"` は `None` になる。
- 桁の多い入力を丸めて受けたいときは、広い型へ `parse` してから `round` する。

（issue #17）

## 12. 名前

演算子、比較、リテラル、型名 `Decimal` は、取り込まずに使える。

演算の名前と `RoundingMode` は、組み込みのモジュール `Austral.Decimal` にある。使うモジュールが明示的に取り込む。

```austral
import Austral.Decimal (RoundingMode, NearestEven, divide, round, widen);
```

このモジュールが持つ名前は、次のとおりである。

- `RoundingMode` と、その7つの case
- `divide`、`checkedDivide`、`checkedAdd`、`checkedSubtract`
- `widen`、`exact`、`checkedExact`、`round`、`checkedRound`、`approximate`
- `parse`

取り込んでいないプログラムの `round` は、ただの利用者の関数である。予約語は増えない。
名前がぶつかるときは、`import Austral.Decimal (round as roundDecimal);` と、名前を変えて取り込む。

演算の呼び出しは、位置で渡す引数だけを取る。演算を関数の値として渡すことはできない。

（issue #24）

## 13. この仕様に含めていないこと

- **P と S を型変数にする汎用の関数。** 「どの精度とスケールでも受ける関数」は、利用者には書けない。後から足しても、既存のコードは壊れない。
- **割り切れなければ失敗する除算と、商と剰余を同時に返す除算。**
- **結果の型を指定して、掛けながら丸める乗算。**
- **演算の名前付きの引数。**
- **文字列やバッファへ書き出す演算。** いまは `print` と `printLn` だけである。
- **編集項目の書式。** 桁区切り、ゼロ抑制、通貨記号は、言語に入れない。
- **通貨と Money 型、複式簿記の線形リソース、按分。**

最後の3つは、要検討の issue #21 で扱う。

## 14. 実装の前に知っておくこと

試作（issue #19）で確かめたことと、今のコンパイラの性質である。

- **算術は、符号なし128ビット整数だけで書ける。** 除算は1桁ずつの筆算にする。128ビットを超えるのは `Float64` からの変換だけである。C の試作は、厳密な計算と 276642 件で一致した。
- **コンパイラの変更は、型の構成子を1つ足す範囲に収まる。** 型レベルの算術も、関数の本体から型引数を読む仕組みも要らない。網羅性の検査が直させる関数は18個である。
- **今のコンパイラの不具合が2件、作業ブランチで直してある。** 算術の片方が定数だと検査なしで切り詰める件（issue #16）と、代入の右辺のリテラルが `Int32` 以外に入らない件（issue #22）である。4節の「代入の右辺」は、後者の修正が前提である。
- **3節と4節のうち、今のコンパイラがまだ行っていないものがある。** 結果の型を位置から取る演算について、`+`、`-`、比較の相手と、関数の引数へ型を渡すこと（試作の追加実験で、約50行で通った）。`if` 式の枝へ型を渡すこと。`/` を含むリテラルの式を、畳み込みで型検査から隠さないこと。リテラルの形を型検査まで運ぶこと。
- **union の C のタグは、宣言の逆順に並ぶ。** `RoundingMode` の case の番号を実行時に渡すなら、順序に頼らない渡し方にするか、順序を保証する。
- **取り込んだ名前は、同じ名前の自分の宣言に黙って勝つ。** 自動の取り込みでも、明示的な `import` でも同じである。
- **実行時の C は、libc の関数を自分で宣言してはいけない。** プログラムが同じ関数を取り込むと、C の宣言が衝突する。
- **検証は2層に分ける。** 算術の意味論は、実行時の C を厳密な計算と突き合わせる。言語の規則は、`test-programs/suites/` に Decimal のスイートを足す（issue #18）。
