# Decimal 型の仕様

Zustral の組み込みの10進固定小数点型 `Decimal[P, S]` の仕様である。
金額のように、桁と丸めを間違えてはいけない値を扱うための型である。

この文書は、何をどう書けて、何が起きるかだけを書く。
なぜそう決めたかは、各節の末尾に挙げた issue の解消コメントにある。
決定の索引は issue #9 にある。

**状態。** 仕様は決まっている。実装はまだない。
実装の順序は `docs/plan.md` にある。実装の前に、コンパイラを作り直す。その計画は `docs/refactoring-plan.md` にある。
使い捨ての試作が `docs/research/decimal-prototype/` にあり、この仕様の大半を動かして確かめてある。試作の後に変えた点は、17節に挙げる。

## 1. 型

`Decimal[P, S]` は、全体で P 桁、小数点より下が S 桁の、符号付きの10進数である。
P を精度、S をスケールと呼ぶ。

```austral
let price: Decimal[9, 2] := 1980.00;
let rate: Decimal[5, 4] := 0.0825;
```

- 引数は必ず2つ書く。`Decimal` だけ、`Decimal[7]` はコンパイルエラーになる。
- P と S は、符号も桁区切りも付けない10進の整数リテラルで書く。定数の名前、式、型変数は書けない。
- 1 ≤ P ≤ 38、0 ≤ S ≤ P である。範囲の外はコンパイルエラーになる。
- 表せる値は、絶対値が 10 の (P − S) 乗未満で、小数部が S 桁までの数である。`Decimal[7, 2]` なら −99999.99 から 99999.99 までである。範囲は正負で対称である。
- P か S が違えば、別の型である。型の違う Decimal の間に、暗黙の変換はない。
- Free の型である。自由に複製でき、破棄できる。
- Free の型を書けるところなら、どこにでも書ける。レコードの欄、union の case、`Option[Decimal[7, 2]]` のような型引数、配列や Span の要素である。
- `Decimal` という型名は、`Int32` と同じく、取り込まずに使える。利用者が `Decimal` という名前の型を宣言すると、コンパイルエラーになる。

（issue #4、#5、#24）

## 2. 実行時の表現

値は係数で持つ。係数は、値を 10 の S 乗倍した整数である。
係数は符号付き128ビット整数に入る。大きさは16バイト固定で、ヒープを使わない。
`sizeof(Decimal[P, S])` は、どの P と S でも 16 である。

同じ型では、1つの値に係数は1つしかない。1.50 と 1.5 は同じ係数になる。
負のゼロ、NaN、無限大はない。

「現在の丸めモード」や「現在の精度」のような、大域の状態はない。どの演算も、引数だけで結果が決まる。

メモリ上のバイトの並びと整列は、この版では約束しない（13節）。

（issue #1、#4、#5）

## 3. リテラル

新しい構文はない。`1.23` や `5` という数値リテラルが、Decimal として読まれる位置で、Decimal になる。

### 3.1 形

Decimal になるのは、指数のない10進の数値リテラルである。

```
符号? 数字 (数字 | ')* ( . (数字 | ')* )?
```

- 符号は `+` か `-` で、先頭に1つまで付く。`-1.50` は1つのリテラルである。
- `'` は桁区切りで、値に関係しない。`1'000.25` は 1000.25 である。
- 先頭の 0 は値に関係しない。`007` は 7 である。
- 小数点の後ろに数字がなくてもよい。`5.` は 5 である。今の言語が `5.` を数値リテラルとして受け付けるのに合わせている。

指数表記（`1.5e3`）、16進、2進、8進、文字のリテラルは、Decimal にならない。Decimal として読まれる位置に書くと、コンパイルエラーになる。`Float64` や整数として渡したいときは、`(1.5e3 : Float64)` や `(#xFF : Nat8)` と型注釈を付ける。型注釈を付けた式は、リテラルではない。

### 3.2 Decimal として読まれる位置

リテラルが Decimal として読まれるのは、次の2種類の位置である。

**Decimal の型が届く位置（4節）。** リテラルは、届いた型になる。
値がその型で正確に表せるリテラルだけを受け付ける。表せなければコンパイルエラーになる。丸めも切り捨てもしない。書いた桁数は関係なく、値だけで決まる。`Decimal[7, 2]` に対する例は次のとおりである。

| リテラル | 結果 |
|---|---|
| `1.5` | 通る。1.50 になる |
| `1.230` | 通る。値は 1.23 である |
| `5` | 通る。5.00 になる |
| `1.234` | エラー。小数3桁目が 0 でない |
| `100000.00` | エラー。整数部が5桁を超える |

**Decimal の演算の引数で、型が届かない位置。** `*` の片方（もう片方が Decimal の式のとき）と、`divide`、`round`、`exact`、`widen`、`approximate`、`checkedDivide`、`checkedRound`、`checkedExact` の引数である。括弧、単項の `-`、`if` 式の枝を通して、中のリテラルもこの位置にある。
ここでは、リテラルは書いた形から自分の型を持つ。
`if` 式の2つの枝の型は、同じでなければならない。`price * (if premium then 0.0500 else 0.0825)` は、どちらの枝も `Decimal[4, 4]` なので通る。`round(if c then 1.5 else 2, m)` は、枝が `Decimal[2, 1]` と `Decimal[1, 0]` になるので、コンパイルエラーになる。

- スケール S は、小数点より後ろに書いた数字の個数である。末尾の 0 も数える。
- 精度 P は、その値をスケール S で表せる最小の精度である。係数の桁数、S、1 のうち、いちばん大きい数になる。`0.0825` の係数は 825 で3桁だが、S が 4 なので P は 4 である。

| リテラル | 型 |
|---|---|
| `2` | `Decimal[1, 0]` |
| `100` | `Decimal[3, 0]` |
| `0.0825` | `Decimal[4, 4]` |
| `1.5` | `Decimal[2, 1]` |
| `1.50` | `Decimal[3, 2]` |
| `0.10` | `Decimal[2, 2]` |
| `0.00` | `Decimal[2, 2]` |

38桁に収まらないリテラルは、コンパイルエラーになる。

スケールを書いたとおりにするのは、掛け算の結果の型を安定させるためである。`price * 0.08` を `price * 0.10` に書き換えても、積のスケールは変わらない。

**どちらでもない位置。** 今までどおりである。小数点付きのリテラルは `Float64`、小数点のないリテラルは整数になる。Decimal にしたいときは、`1.23 : Decimal[7, 2]` と型注釈を付ける。

### 3.3 リテラルだけの式

リテラルだけの式とは、数値リテラルを、括弧、単項の `-`、`+`、`-`、`*`、`/` だけで組んだ式である。
Decimal として読まれる位置では、リテラルだけの式は1つのリテラルとして扱う。

- `+`、`-`、`*`、単項の `-` は、コンパイル時に10進で正確に計算する。
- `/` があれば、コンパイルエラーになる。`7 / 100` を整数の除算で 0 にすることはない。
- 型が届く位置では、計算した値が届いた型で正確に表せるかを検査する。
- 型が届かない位置では、式は自分の型を持つ。スケールは、`+` と `-` では両辺の大きい方、`*` では両辺の和である。括弧と単項の `-` は、中の式のスケールのままである。精度は、計算した値をそのスケールで表せる最小の精度である。`1 + 0.0825` は `Decimal[5, 4]` になる。
- リテラルだけの式は、全体で1つのリテラルである。4節の「型が中へ進む規則」と、5節の演算子の規則は、式の中には当てはめない。`let d: Decimal[4, 4] := 1 - 0.0825;` は通る。値は 0.9175 で、`Decimal[4, 4]` で表せる。途中の 1 が `Decimal[4, 4]` で表せないことは、問わない。

```austral
let with_tax: Decimal[11, 2] := round(price * (1 + 0.0825), NearestEven());
let fee: Decimal[11, 0] := round(amount * (7 / 100), TowardZero());   -- コンパイルエラー
let fee: Decimal[11, 0] := round(amount * 0.07, TowardZero());        -- こう書く
```

（issue #14、#12、#23）

## 4. 型が届く位置

位置は、そこに宣言された型を、中の式へ届ける。
届いた型を使うのは、リテラルと、結果の型を位置から取る演算である。

### 4.1 届いた型に求めること

リテラルと、リテラルだけの式は、届いた型が `Decimal[P, S]` のときに Decimal になる。他の型が届いたときは、今までどおりである。

結果の型を位置から取る演算は、届いた型が次の形であることを求める。

| 演算 | 届いた型 |
|---|---|
| `divide`、`widen` | `Decimal[P, S]` |
| `round`、`exact` | `Decimal[P, S]` か整数型 |
| `checkedDivide`、`parse` | `Option[Decimal[P, S]]` |
| `checkedRound`、`checkedExact` | `Option[Decimal[P, S]]` か、整数型の `Option` |

届いた型がこの形でなければ、コンパイルエラーになる。
型が届かない位置に書いても、コンパイルエラーになる。既定の結果の型はない。

### 4.2 型を届ける位置

型を届ける位置は、次のものだけである。

| 位置 | 届く型 |
|---|---|
| `let` と `var` | 型注釈の型 |
| `return` | 戻り値の型 |
| 型注釈 `式 : 型` | 書いた型 |
| 代入の右辺 | 代入先の型。`total := 0;`、`r.amount := round(x, m);` |
| 関数、メソッド、関数ポインタの呼び出しの引数 | 引数の宣言の型。型変数を含まない場合に限る |
| レコードと union の構成子の欄 | 欄の宣言の型。型変数を含まない場合に限る |
| `+`、`-`、比較の両辺 | 相手の型。`widen(a) + tax` では、`tax` の型が `widen(a)` に届く |
| `checkedAdd`、`checkedSubtract` の2つの引数 | 相手の型 |
| 定数の宣言 | 宣言の型。リテラルとリテラルだけの式にだけ届く |

定数の初期値に書けるのは、リテラル、リテラルだけの式、同じ型の他の定数の名前である。演算子を使った式（リテラルだけの式を除く）と、演算の呼び出しは書けない。今の言語の、定数の初期値の規則である（issue #59）。

### 4.3 届いた型が中へ進む規則

**自分で型が決まらない式**とは、次のものである。それ以外の式は、自分で型が決まる。

- リテラルと、リテラルだけの式。
- 結果の型を位置から取る演算。
- それらを、括弧か単項の `-` で包んだ式。
- 枝のどちらかが、自分で型が決まらない式である `if` 式。

届いた型は、次のものを通って中へ進む。

- 括弧と、単項の `-`。
- `if` 式の2つの枝。`if premium then 0.0500 else 0.0825` の両方に届く。片方の枝の型が、もう片方へ届くことはない。
- `+` と `-` の両辺。ただし、相手が自分で型の決まる式なら、相手の型が先に届く。両辺とも自分で型が決まらないときに、外から届いた型が両辺に届く。
- `checkedAdd` と `checkedSubtract` の2つの引数。`Option[Decimal[P, S]]` が届いたとき、中の `Decimal[P, S]` が、`+` と同じ規則で引数に届く。

`+`、`-`、比較、`checkedAdd`、`checkedSubtract` で、両辺とも自分で型が決まらず、外からも Decimal の型が届かないときは、次のようになる。

- どちらかに、結果の型を位置から取る演算があれば、コンパイルエラーになる。
- 両辺ともリテラルかリテラルだけの式なら、Decimal の演算ではない。今までどおり、整数か `Float64` の演算である。`if 1 < 2` や `printLn(1 + 2)` は、今までと同じ意味である。

型が届かなかった `if` 式の枝も、同じである。枝のリテラルは、今までどおりの型になる。`printLn(if c then a else 0)` は、`a` が Decimal なら、枝の型が合わずにコンパイルエラーになる。`0 : Decimal[7, 2]` と型注釈を付ける。

届いた型は、次のものを通らない。ここに結果の型を位置から取る演算を書くときは、型注釈を付ける。

- `*` の両辺。
- `divide`、`round`、`exact`、`widen`、`approximate` と、その `checked` の形の引数。`round(divide(a, b, m), m2)` は通らず、`round(divide(a, b, m) : Decimal[13, 6], m2)` と書く。
- 比較の両辺へは、相手の型だけが届く。比較の式に届いた型（`Bool`）は進まない。
- 型変数として宣言された引数や欄。`Some(value => 1.23)` は通らず、`Some(value => 1.23 : Decimal[7, 2])` と書く。全体の型が `Option[Decimal[7, 2]]` と分かっていても同じである。今の言語の規則であり、整数のリテラルでも同じである（issue #55）。
- `case` 文で調べる式と、`if` の条件。

（issue #6、#15、#23）

## 5. 演算の一覧

| 書き方 | 入力 | 結果の型 | 丸め | 失敗 |
|---|---|---|---|---|
| `a + b`、`a - b` | 同じ型の Decimal どうし | 入力と同じ | なし | 桁あふれで止まる |
| `checkedAdd(a, b)`、`checkedSubtract(a, b)` | 同じ型の Decimal どうし | `Option`（入力と同じ型） | なし | `None` |
| `-a` | Decimal | 入力と同じ | なし | しない |
| `a * b` | Decimal どうし、または Decimal と整数型 | `Decimal[P1 + P2, S1 + S2]` | なし | しない |
| `divide(a, b, mode)` | Decimal か整数型 | 位置から取る Decimal | あり | 桁あふれとゼロ除算で止まる |
| `checkedDivide(a, b, mode)` | Decimal か整数型 | 位置から取る `Option` | あり | `None` |
| `widen(x)` | Decimal か整数型 | 位置から取る Decimal | なし | しない |
| `exact(x)` | Decimal か整数型 | 位置から取る | なし | 正確に表せなければ止まる |
| `checkedExact(x)` | Decimal か整数型 | 位置から取る `Option` | なし | `None` |
| `round(x, mode)` | Decimal、整数型、`Float64` | 位置から取る | あり | 桁あふれと、NaN、無限大で止まる |
| `checkedRound(x, mode)` | Decimal、整数型、`Float64` | 位置から取る `Option` | あり | `None` |
| `approximate(x)` | Decimal | `Float64` | 最も近い値 | しない |
| `=`、`/=`、`<`、`<=`、`>`、`>=` | 同じ型の Decimal どうし | `Bool` | なし | しない |
| `print(x)`、`printLn(x)` | Decimal | `Unit` | なし | しない |
| `parse(text)` | `Span[Nat8, R]` | 位置から取る `Option` | なし | `None` |

### 5.1 加算、減算、比較

- 両辺の型が違えば、コンパイルエラーになる。`widen` でそろえてから足す。
- 整数型の値は、そのままでは足せない。`amount + widen(count)` と書く。`widen` には、相手の型が届く。
- 片方がリテラルなら、リテラルは相手の型になる。`rate + 1` は、`rate` が `Decimal[4, 4]` ならコンパイルエラーになる。1 がその型で表せないためである。`widen(rate) + 1` を、`Decimal[5, 4]` の位置で使う。

### 5.2 乗算

- 結果は正確な積である。型は `Decimal[P1 + P2, S1 + S2]` になる。丸めも桁あふれも起きない。
- P1 + P2 が 38 を超えると、コンパイルエラーになる。先にどちらかを狭い型へ変換してから掛ける。
- 積の型が、届いた型と違えば、コンパイルエラーになる。積を暗黙に広げることはない。
- **整数型の値を、そのまま掛けられる。** 整数は正確な値なので、丸めの問題がない。型の計算では、整数型を `Decimal[桁数, 0]` として数える。桁数は9節の表にある。`price * quantity` は、`price` が `Decimal[9, 2]`、`quantity` が `Int32` なら `Decimal[19, 2]` になる。
- 整数のリテラルは、値の桁数で数える。`price * 3` は `Decimal[10, 2]` である。変数は、型の桁数で数える。
- 両辺とも整数型なら、今までどおりの整数の乗算である。Decimal の演算ではない。
- `Float64` は掛けられない。先に `round` で Decimal にする。

### 5.3 除算

- `/` は Decimal には使えない。コンパイルエラーになり、`divide` を使う。
- `divide(a, b, mode)` の `a` と `b` は、Decimal でも整数型でもよい。型が違ってよい。整数型の値は、乗算と同じく `Decimal[桁数, 0]` として扱う。`divide(total, count, TowardZero())` と書ける。
- 結果は Decimal に限る。整数型では受けられない。
- 割る数がリテラルで、値が 0 なら、コンパイルエラーになる。リテラルだけの式でも同じである。
- **Decimal の演算の引数に、整数の `/` は書けない。** `*` の片方、`divide`、`round`、`exact`、`widen` と、その `checked` の形の引数の式に、整数の `/` があれば、コンパイルエラーになる。括弧、単項の `-`、`+`、`-`、`*`、`if` 式の枝を通して調べる。関数の呼び出しの中までは調べない。

  ```austral
  let interest: Decimal[11, 0] := round(balance * (days / 365), TowardZero());   -- コンパイルエラー
  let interest: Decimal[11, 0] := divide(balance * days, 365, TowardZero());      -- こう書く
  ```

  整数の `/` は、小数部を黙って切り捨てる。`days / 365` は、365 日未満なら 0 になる。金額の式でこれが通ると、間違った金額が黙って出る。意図して整数の除算を使うときは、先に `let` で変数へ入れてから渡す。

### 5.4 評価

- どの演算も、引数をちょうど1回ずつ評価する。演算が失敗するときも、すべての引数を評価する。
- 引数を評価する順は、関数の引数と同じである。今の言語は、この順を決めていない（issue #53）。
- 演算子に優先順位はない。2つ以上の演算子を並べるときは、括弧で順序を書く。これは今の言語の規則である。

### 5.5 例

```austral
-- unit_price: Decimal[9, 0]、quantity: Int32、discount: Decimal[11, 0]
let gross: Decimal[19, 0] := unit_price * quantity;
let subtotal: Decimal[19, 0] := gross - widen(discount);
let tax: Decimal[11, 0] := round(subtotal * 0.10, TowardZero());     -- 円未満切り捨て
let per_person: Decimal[11, 0] := divide(subtotal, 3, TowardZero());
let total: Decimal[20, 0] := widen(subtotal) + widen(tax);
```

（issue #6、#12、#15、#17）

## 6. 結果の決め方

どの演算も、次の順で結果を決める。

1. 数学的に正確な値を求める。途中の値を何桁かで切り詰めることはしない。割る数が 0 なら、正確な値がないので、ここで失敗する。
2. 丸めモードを取る演算なら、結果の型のスケールへ、1回だけ丸める。結果が整数型なら、整数へ丸める。
3. 結果の型の範囲と比べる。結果が `Decimal[P, S]` なら、係数の絶対値が 10 の P 乗以上のときに桁あふれである。結果が整数型なら、その型の最小値から最大値までに入らないときに桁あふれである。

丸めてから桁あふれを検査する。
999.96 を `Decimal[4, 1]` へ `NearestAwayFromZero` で丸めると、1000.0 に丸め上がって桁あふれになる。

（issue #7、#8）

## 7. 丸め

暗黙の丸めはない。既定の丸めモードもない。
Decimal か整数を返す演算で、桁を落としうるものは、必ず丸めモードを引数に取る。丸めモードを取るのは、`divide` と `round`、その `checked` の形だけである。
`Float64` を返す `approximate` だけは、丸めモードを取らない。最も近い値にする（9.4節）。

丸めモードは、組み込みの union 型 `RoundingMode` の値である。case は7つある。

### 7.1 定義

結果の型のスケールで表せる値を、目盛りと呼ぶ。
正確な値が目盛りの上にあれば、どのモードでも結果はその値である。
そうでなければ、正確な値は、隣り合う2つの目盛りの間にある。モードは、そのどちらを取るかを決める。

| case | 取る目盛り |
|---|---|
| `TowardGreater` | 大きい方 |
| `TowardLesser` | 小さい方 |
| `TowardZero` | 0 に近い方（切り捨て） |
| `AwayFromZero` | 0 から遠い方（切り上げ） |
| `NearestEven` | 近い方。ちょうど真ん中なら、係数が偶数の方（銀行丸め） |
| `NearestAwayFromZero` | 近い方。ちょうど真ん中なら、0 から遠い方（四捨五入） |
| `NearestTowardZero` | 近い方。ちょうど真ん中なら、0 に近い方 |

### 7.2 例

小数2桁へ丸めた結果である。

| case | 2.345 | 2.355 | −2.345 | 2.344 |
|---|---|---|---|---|
| `NearestEven` | 2.34 | 2.36 | −2.34 | 2.34 |
| `NearestAwayFromZero` | 2.35 | 2.36 | −2.35 | 2.34 |
| `NearestTowardZero` | 2.34 | 2.35 | −2.34 | 2.34 |
| `AwayFromZero` | 2.35 | 2.36 | −2.35 | 2.35 |
| `TowardZero` | 2.34 | 2.35 | −2.34 | 2.34 |
| `TowardGreater` | 2.35 | 2.36 | −2.34 | 2.35 |
| `TowardLesser` | 2.34 | 2.35 | −2.35 | 2.34 |

この表と、3.2節のリテラルの型の表は、`python3 docs/check-decimal-tables.py` で計算し直せる。

### 7.3 COBOL との対応

| COBOL | Zustral |
|---|---|
| `ROUNDED` を書かない | `TowardZero` |
| `ROUNDED`（`MODE` なし） | `NearestAwayFromZero` |
| `ROUNDED MODE IS TRUNCATION` | `TowardZero` |
| `ROUNDED MODE IS NEAREST-AWAY-FROM-ZERO` | `NearestAwayFromZero` |
| `ROUNDED MODE IS NEAREST-EVEN` | `NearestEven` |
| `ROUNDED MODE IS NEAREST-TOWARD-ZERO` | `NearestTowardZero` |
| `ROUNDED MODE IS AWAY-FROM-ZERO` | `AwayFromZero` |
| `ROUNDED MODE IS TOWARD-GREATER` | `TowardGreater` |
| `ROUNDED MODE IS TOWARD-LESSER` | `TowardLesser` |
| `ROUNDED MODE IS PROHIBITED` | `exact`、`checkedExact` |

COBOL は、書かなければ切り捨てる。Zustral は、書かなければコンパイルが通らない。
「丸めが要るなら失敗にする」は、丸めモードではない。`exact` と `checkedExact` を使う。

GnuCOBOL での実測は `docs/research/cobol-decimal-semantics/` にある。

（issue #3、#7）

## 8. 失敗

桁あふれしうる演算には、2つの形がある。

- **止まる形。** 失敗すると、メッセージを出してプログラムを止める。演算子と、`checked` の付かない名前の演算がこれである。整数の桁あふれと同じ扱いである。
- **検査する形。** 結果を `Option` で返し、失敗なら `None` にする。`checked` の付く名前の演算がこれである。失敗の理由は返さない。

ゼロ除算も同じに扱う。`divide` は止まり、`checkedDivide` は `None` を返す。

黙って桁を落とす演算はない。あふれた分を捨てて続ける演算も、上限に張り付かせる演算もない。

### 8.1 止まるときのメッセージ

メッセージは、stderr に1行で出る。形は、整数の桁あふれ（`Overflow in trappingAdd (Int8)`）に合わせる。

```
失敗の種類 in 演算 (結果の型)
```

| 演算 | 失敗 | メッセージの例 |
|---|---|---|
| `a + b` | 桁あふれ | `Overflow in add (Decimal[7, 2])` |
| `a - b` | 桁あふれ | `Overflow in subtract (Decimal[7, 2])` |
| `divide` | ゼロ除算 | `Division by zero in divide (Decimal[9, 4])` |
| `divide` | 桁あふれ | `Overflow in divide (Decimal[9, 4])` |
| `round` | 桁あふれ | `Overflow in round (Decimal[4, 1])` |
| `round` | 元が NaN か無限大 | `Not finite in round (Decimal[4, 1])` |
| `exact` | 丸めが要る | `Inexact in exact (Decimal[7, 2])` |
| `exact` | 範囲の外 | `Overflow in exact (Int32)` |

- 括弧の中は、結果の型である。
- `exact` で、丸めが要り、かつ範囲の外でもあるときは、`Inexact` を出す。
- 終了コードは、整数の桁あふれと同じである。今は 255 である。
- メッセージにソースの位置を足すことは、整数のトラップと一緒に issue #58 で扱う。
- 今の実行時は、止まるときに stdout のバッファを書き出さない（issue #52）。

（issue #8）

## 9. 変換

型注釈 `式 : 型` は、値を変換しない。変換は、次の演算で書く。変換先の型は、位置から取る。

| 演算 | 意味 | 失敗 |
|---|---|---|
| `widen(x)` | 元の型のどの値も、変換先で正確に表せる変換 | しない。表せない組み合わせはコンパイルエラー |
| `exact(x)` | 値を変えずに移す変換 | 値が変換先で正確に表せないとき |
| `round(x, mode)` | 変換先のスケールへ丸める変換 | 丸めた後の桁あふれ。元が NaN か無限大のとき |
| `approximate(x)` | 最も近い `Float64` にする変換 | しない |

### 9.1 元と先

| 演算 | 元 | 先 |
|---|---|---|
| `widen` | Decimal、整数型 | Decimal |
| `exact` | Decimal、整数型 | Decimal、整数型 |
| `round` | Decimal、整数型、`Float64` | Decimal、整数型 |
| `approximate` | Decimal | `Float64` |

- `exact` と `round` では、元と先の少なくとも一方が Decimal でなければならない。両方が Decimal でもよい。整数から整数、`Float64` から整数は、この演算の仕事ではない。
- 整数型とは、`Nat8`、`Nat16`、`Nat32`、`Nat64`、`Int8`、`Int16`、`Int32`、`Int64`、`Index`、`ByteSize` である。
- `Float32` は受け付けない。先に `Float64` へ変換する。
- Decimal は、`ToInt64` や `ToFloat64` などの変換の型クラスのインスタンスではない。

### 9.2 `widen` が通る条件

`widen` が通るかどうかは、型だけで決まる。

- `Decimal[P, S]` から `Decimal[P', S']` へは、S' ≥ S かつ P' − S' ≥ P − S のときに通る。同じ型へも通る。
- 整数型からは、その型の最大の桁数が P' − S' 以下のときに通る。桁数は次のとおりである。

  | 型 | 桁数 |
  |---|---|
  | `Nat8`、`Int8` | 3 |
  | `Nat16`、`Int16` | 5 |
  | `Nat32`、`Int32` | 10 |
  | `Int64` | 19 |
  | `Nat64`、`Index`、`ByteSize` | 20 |

この表は、乗算と除算で整数型を `Decimal[桁数, 0]` として数えるときにも使う（5節）。

### 9.3 `exact` と `round`

- 変換先が Decimal のとき、`exact` は、値の小数部が S' 桁に収まり、絶対値が 10 の (P' − S') 乗未満のときに成功する。
- 変換先が整数型のとき、`exact` は、値が整数で、その型の最小値から最大値までに入るときに成功する。負の値は、符号なしの型へは移せない。
- `round` は、変換先のスケールへ丸めてから、同じ範囲の検査をする。変換先が整数型なら、整数へ丸める。
- 丸めが起きない組み合わせでも、`round` は書ける。整数からの変換と、スケールが減らない変換である。丸めモードは使われない。
- `Float64` からの `round` は、その2進の値を正確な値として丸める。0.1 と書いた `Float64` は、0.1 より少し大きい値として扱われる。NaN と無限大は失敗になる。負のゼロは 0 になる。

### 9.4 `approximate`

- 最も近い `Float64` を返す。ちょうど真ん中なら、仮数が偶数の方を返す。IEEE 754 の既定の丸めと同じである。
- 浮動小数点の丸めの設定に左右されない。
- 0 は正のゼロになる。
- 失敗しない。Decimal の絶対値は 10 の 38 乗未満で、`Float64` の範囲に収まる。
- Decimal の値が正確に保たれない変換は、これ1つである。

（issue #15）

## 10. 比較

`=`、`/=`、`<`、`<=`、`>`、`>=` は、同じ型の Decimal どうしで使える。
型が違えばコンパイルエラーになる。`widen` でそろえてから比べる。

片方がリテラルなら、リテラルは相手の型になる。左右どちらにあっても同じである。
`balance < 0` と書ける。

比較は全順序である。NaN も負のゼロもない。

（issue #15）

## 11. 文字列

### 11.1 正準の表記

Decimal の正準の表記は1つである。

- 負のときだけ `-` を付ける。
- 整数部は、先頭の 0 を付けずに、最低1桁を書く。
- 続けて、小数点と、ちょうど S 桁の小数部を書く。S が 0 なら、小数点も書かない。
- 桁区切り、指数、正の符号、空白は付けない。
- 文字は ASCII である。長さは最大で P + 3 バイトである。

`Decimal[7, 2]` では、1.5 は `1.50`、−0.05 は `-0.05`、0 は `0.00` になる。

### 11.2 出力

すべての Decimal の型は、型クラス `Printable` のインスタンスである。インスタンスはコンパイラが用意する。

- `print(x)` と `printLn(x)` は、正準の表記を stdout に出す。
- `Printable` を制約に持つ汎用の関数に、Decimal を渡せる。
- 利用者は、`Printable` のインスタンスを Decimal の型に宣言できない。
- `printSpan` は、整数型のインスタンスと同じ動きにする。今は何も出力しない（issue #60）。
- `printLn(1.50)` は、Decimal ではなく `Float64` を出力する。`printLn` の引数は型変数なので、型が届かないためである。

出力先は stdout だけである。バイト列へ書き出す演算は、まだない（issue #64）。

### 11.3 `parse`

`parse(text)` は、バイト列から Decimal を読む。結果は位置から取る `Option` である。

- 受け付ける形は、省略できる符号（`+` か `-`）、1桁以上の数字、省略できる「小数点と1桁以上の数字」である。文字は ASCII に限る。`"+1.50"` は読める。
- 桁区切り、指数、前後の空白、`.5`、`5.`、空の入力、符号だけの入力は `None` になる。
- 値がその型で正確に表せるときだけ `Some` を返す。丸めない。`Decimal[7, 2]` に対して、`"1.5"`、`"1.500"`、`"007.50"` は読め、`"1.234"` と `"100000.00"` は `None` になる。
- 長さの上限はない。結果は値だけで決まる。先頭や末尾に 0 が何桁あっても同じである。
- `"-0"` と `"-0.00"` は 0 になる。
- 正準の表記は必ず読める。同じ型で、出力したものを `parse` すると、元の値の `Some` になる。
- 桁の多い入力を丸めて受けたいときは、広い型へ `parse` してから `round` する。

リテラル（3節）と `parse` は、受け付ける形が違う。リテラルは言語の字句で、桁区切りと `5.` を許す。`parse` はデータの形式で、許さない。

（issue #17）

## 12. 名前

演算子、比較、リテラル、型名 `Decimal` は、取り込まずに使える。

演算の名前と `RoundingMode` は、組み込みのモジュール `Austral.Decimal` にある。使うモジュールが明示的に取り込む。

```austral
import Austral.Decimal (RoundingMode, NearestEven, divide, round, widen);
```

このモジュールが持つ名前は、次のとおりである。

- `RoundingMode` と、その7つの case
- `divide`、`checkedDivide`、`checkedAdd`、`checkedSubtract`
- `widen`、`exact`、`checkedExact`、`round`、`checkedRound`、`approximate`
- `parse`

取り込んでいないプログラムの `round` は、ただの利用者の関数である。予約語は増えない。
名前がぶつかるときは、`import Austral.Decimal (round as roundDecimal);` と、名前を変えて取り込む。
今のコンパイラは、名前を変えて取り込んだ型と union の case を正しく扱えない（issue #50）。関数では通る。

演算の呼び出しは、位置で渡す引数だけを取る。演算を関数の値として渡すことはできない（issue #67）。

モジュールの名前が `Austral.` で始まるのは、今の組み込みのモジュールに合わせたためである。言語の名前の扱いは、issue #46 で決める。

（issue #24）

## 13. 型クラスと外部関数

### 13.1 型クラス

- 利用者は、自分の型クラスのインスタンスを、具体的な Decimal の型に宣言できる。`instance Describable(Decimal[11, 2])` と書く。
- 型クラスは、インスタンスと同じモジュールで宣言したものに限る。他のモジュールの型クラスのインスタンスを Decimal の型に宣言すると、コンパイルエラーになる。`Int32` に自分の型クラスのインスタンスを宣言できるのと同じ扱いである。
- `Decimal[11, 2]` と `Decimal[13, 2]` のインスタンスは、別のものである。すべての Decimal の型をまとめて受けるインスタンスは書けない。
- Decimal は、`TrappingArithmetic`、`ModularArithmetic`、`BitwiseOperations` のインスタンスではない。これらを制約に持つ汎用の関数には渡せない。
- stdlib の `Standard.Equality` と `Standard.Order` のインスタンスは、コンパイラが作らない（issue #44）。

### 13.2 外部関数

- Decimal を、外部関数（`Foreign_Import`、`Foreign_Export`）の引数と戻り値に、値で書くとコンパイルエラーになる。
- `Address`、`Pointer`、`Span` の要素としては、他の型と同じく書ける。ただし、メモリ上のバイトの並びと整列は、この版では約束しない。C の側で中身を読んではいけない。
- C へ金額を渡すときは、整数か文字に直す。`exact(amount * 100)` を `Int64` の位置で使えば、小数2桁の金額が、最小単位の整数になる。

並びを約束するかどうかは、issue #69 で扱う。

## 14. コンパイルエラーの一覧

この仕様が定めるコンパイルエラーを、1か所にまとめる。

**型**

- `Decimal[P, S]` の引数が2つでない。引数が、符号も桁区切りもない整数リテラルでない。
- P が 1 から 38 の外にある。S が 0 から P の外にある。
- 利用者が `Decimal` という名前の型を宣言した。

**リテラル**

- 届いた型で、値を正確に表せない。
- Decimal として読まれる位置に、指数表記、16進、2進、8進、文字のリテラルがある。
- 型が届かない位置のリテラルが、38桁に収まらない。
- Decimal として読まれる位置の、リテラルだけの式に `/` がある。

**演算子**

- `+`、`-`、比較、`checkedAdd`、`checkedSubtract` の両辺の型が違う。片方が整数型か `Float64` である場合を含む。
- `+`、`-`、比較、`checkedAdd`、`checkedSubtract` の両辺とも自分で型が決まらず、外からも型が届かず、どちらかに結果の型を位置から取る演算がある。
- `if` 式の2つの枝の型が違う。
- `*` で、P1 + P2 が 38 を超える。
- `*` の結果の型が、届いた型と違う。
- `*` か `divide` に、`Float64` の値を渡した。
- Decimal に `/` を使った。
- Decimal の演算の引数に、整数の `/` がある。
- `divide` と `checkedDivide` の割る数が、値が 0 のリテラルである。

**型が届く位置**

- 結果の型を位置から取る演算を、型が届かない位置に書いた。
- 届いた型が、その演算の求める形（4.1節）でない。

**変換**

- `widen` の元と先の型が、通る条件（9.2節）を満たさない。
- 演算の引数が、5節の表の入力の型でない。`exact` と `widen` に `Float64` を渡した、`approximate` に整数型を渡した、など。
- `exact` か `round` で、元も先も Decimal でない。
- `round` の元が `Float32` である。

**その他**

- 定数の初期値に、リテラル、リテラルだけの式、同じ型の他の定数の名前のどれでもない式を書いた。
- 外部関数の引数か戻り値に、Decimal を値で書いた。
- 利用者が、他のモジュールの型クラスのインスタンスを Decimal の型に宣言した。`Printable` を含む。
- 演算の呼び出しに、名前付きの引数を使った。演算を関数の値として使った。

## 16. 書き方の例

レビューで、利息、請求書、ローン、按分の4つの計算を、この仕様だけで書いた。そこで分かった書き方をまとめる。

**積は、宣言した型で受ける。** 積の型は、掛けた2つの型から決まる。そのまま束縛すると、元の型を変えたときに、積の型も書き直すことになる。`round`、`exact`、`widen`、`divide` に直接渡せば、積の型を書かずに済む。

```austral
let tax: Decimal[11, 0] := round(subtotal * 0.10, TowardZero());
```

**率は、型を付けた定数にする。** リテラルを式に直接書くと、値を変えたときに積の型が変わりうる。定数にすれば変わらない。

```austral
constant TAX_RATE: Decimal[3, 2] := 0.10;
```

**広く計算して、格納するところで検査する。** 途中は正確な積と広い型で持ち、最後に1回だけ丸める。不正なデータで止めたくないバッチでは、最後を `checkedRound` にして、`None` のレコードをよける。

```austral
let stored: Option[Decimal[11, 0]] := checkedRound(balance * rate, TowardZero());
```

**等分は、割ってから残りを寄せる。** 100 円を3人で分けると、33 円、33 円、34 円になる。

```austral
let share: Decimal[11, 0] := divide(total, 3, TowardZero());
let last: Decimal[11, 0] := (total - share) - share;
```

**日数や数量は、そのまま掛ける。** 割るのは最後に1回である。

```austral
let interest: Decimal[11, 0] := divide((balance * days) * rate, 365, TowardZero());
```

**COBOL の書き方との対応。**

| COBOL | Zustral |
|---|---|
| `COMPUTE X = A * B` | `x := round(a * b, TowardZero());` |
| `COMPUTE X ROUNDED = A * B` | `x := round(a * b, NearestAwayFromZero());` |
| `ON SIZE ERROR` | `checked` の付く演算と `case` |
| `MOVE A TO B`（桁が減る） | `b := exact(a);` か `b := round(a, mode);` |

COBOL は、`ON SIZE ERROR` を書かなければ、あふれた上位の桁を黙って落とす。Zustral に、黙って桁を落とす書き方はない。

## 17. 実装の前に知っておくこと

試作（issue #19）で確かめたことと、今のコンパイラの性質である。

**試作で確かめたこと**

- **算術は、符号なし128ビット整数だけで書ける。** 除算は1桁ずつの筆算にする。128ビットを超えるのは `Float64` からの変換だけである。C の試作は、厳密な計算と 276642 件で一致した。
- **コンパイラの変更は、型の構成子を1つ足す範囲に収まる。** 型レベルの算術も、関数の本体から型引数を読む仕組みも要らない。網羅性の検査が直させる関数は18個である。
- **検証は2層に分ける。** 算術の意味論は、実行時の C を厳密な計算と突き合わせる。言語の規則は、`test-programs/suites/` に Decimal のスイートを足す（issue #18）。

**試作の後に、この仕様で変えた点**

試作は、次の点でこの仕様と違う。試作は直さない。

- 型が届かない位置のリテラルを、値を表せる最小の型にしている。この仕様は、スケールを書いたとおりにする（3.2節）。
- 整数型の値を `*` と `divide` に渡すと、コンパイルエラーにしている。この仕様は受け付ける（5節）。
- Decimal の演算の引数にある整数の `/` を、検査していない。
- Decimal から整数型への変換がない。
- `checked` の形が、引数を2回評価する。この仕様は1回である。
- `checkedAdd` と `checkedSubtract` が、位置から `Option` の型が届くことを求める。この仕様は求めない。結果の型は、引数の型から決まる。
- 定数を C の `#define` で出すので、使うたびに計算し直す。
- 止まるときのメッセージが、8.1節の形でない。
- `approximate` と、`Float64` からの変換が、libc の `strtod` に頼っている（issue #68）。
- 出力は、試験用の関数である。`Printable` のインスタンスではない。

**今のコンパイラの性質**

- **不具合が2件、作業ブランチで直してある。** 算術の片方が定数だと検査なしで切り詰める件（issue #16）と、代入の右辺のリテラルが `Int32` 以外に入らない件（issue #22）である。4節の「代入の右辺」は、後者の修正が前提である。
- **4節のうち、まだ行っていないものがある。** 結果の型を位置から取る演算について、`+`、`-`、比較の相手と、関数の引数へ型を渡すこと（試作の追加実験で、約50行で通った）。`if` 式の枝へ型を渡すこと（issue #35）。
- **リテラルだけの式は、型検査の前に畳み込まれる。** `/` も整数の除算で畳み込まれ、型検査からは見えない（issue #37）。`7 / 0` はコンパイラを落とす（issue #49）。3.3節の規則は、畳み込みより前に検査する必要がある。
- **リテラルの形は、型検査まで届かない。** 16進か10進か、小数部を何桁書いたかが、途中で失われる（issue #38）。3.1節と3.2節は、これを運ぶ必要がある。
- **数値リテラルの字句が、余分な符号を受け付ける。** `1.+5` が1つのリテラルになる（issue #47）。`a+5` は構文エラーになる（issue #48）。単項の `-` は `0 - x` に展開される（issue #26）。
- **先頭に 0 のある整数リテラルは、C で8進数として読まれる。** `010` は 8 になる（issue #88）。3.1節は、先頭の 0 が値に関係しないと決めている。
- **union の C のタグは、宣言の逆順に並ぶ**（issue #39）。`RoundingMode` の case の番号を実行時に渡すなら、順序に頼らない渡し方にするか、順序を保証する。
- **取り込んだ名前は、同じ名前の自分の宣言に黙って勝つ**（issue #28）。組み込みの型と同じ名前の型も宣言できてしまう（issue #51）。
- **外部関数に使えない型の検査は、C を生成する段にある。** エラーは「Not allowed」だけである（issue #54）。13.2節の検査は、ここを直してから載せる。
- **組み込みの型には、孤児の規則が効いていない。** `instance Printable(Int32)` を宣言でき、呼び出しでコンパイラの内部エラーになる（issue #72）。11.2節と13.1節の検査は、ここを直してから載せる。
- **実行時の C は、libc の関数を自分で宣言してはいけない。** プログラムが同じ関数を取り込むと、C の宣言が衝突する。
